# Dataverse Patterns & Learnings

Reference for current and future Dataverse work in Playbook Agent.

## SDK Access Pattern (PAC CLI Code Apps)

The PAC CLI generates typed services in `PlaybookAgent/src/generated/`:
- **Models** (`models/*.ts`): TypeScript interfaces for each entity
- **Services** (`services/*.ts`): Static classes with `create`, `update`, `delete`, `get`, `getAll`, `getMetadata`

All services use `getClient(dataSourcesInfo)` from `@microsoft/power-apps/data`. Auth is handled by the Power Apps host — no tokens, no fetch, no axios.

## Generated Service API

```typescript
// List with structured options (NOT raw query strings)
Service.getAll({ top: 10, filter: "name eq 'Test'", select: ['name', 'teamid'], orderBy: ['name asc'] })

// Get by ID
Service.get(id, { select: ['name'] })

// Create — Omit the primary key (auto-generated)
Service.create({ name: 'Test', 'LookupField@odata.bind': '/tablename(guid)' })

// Update — Partial fields
Service.update(id, { name: 'Updated' })

// Delete
Service.delete(id)

// Metadata
Service.getMetadata()
```

## Lookup Binding

Dataverse lookups require `@odata.bind` format:
```typescript
// Helper in sdk.ts:
lookupBind('systemusers', 'abc-123')  // → "/systemusers(abc-123)"

// Usage:
TeamsService.create({
  name: 'My Team',
  'BusinessUnitId@odata.bind': lookupBind('businessunits', buId),
  'AdministratorId@odata.bind': lookupBind('systemusers', userId),
  teamtype: 0,
  membershiptype: 0,
})
```

## OData Filter Escaping

Always escape single quotes in user-provided filter values:
```typescript
escapeOData("O'Brien")  // → "O''Brien"
```

## Active-Version Semantics

For config-like entities, only read active records:
```typescript
filter: "statecode eq 0"
```

## Adding a New Table

When a new table is added via PAC CLI:

1. Run `pac code add` for the new table
2. Register in `sdk.ts` TABLES constant:
   ```typescript
   jw_agent: { name: 'jw_agents', primaryKey: 'jw_agentid' }
   ```
3. Add traced CRUD wrappers in `dataverse.ts`
4. Add hook functions in `useDataverse.ts`
5. Register in DataverseExplorer AVAILABLE_TABLES
6. Update CLAUDE.md data model section

## Response Shape

`IOperationResult<T>` has:
- `data: T` — the typed result
- Other platform metadata

For lists: `IOperationResult<T[]>` where `data` is the array of records.

## Known Gotchas

- `orderBy` must be an array of strings: `['name asc']`, not a raw string
- `filter` is a raw OData string — caller must escape values
- `TeamsBase` requires `teamtype` and `membershiptype` as numeric keys (0, 1, 2, 3)
- `create` omits the primary key field (it's auto-generated by Dataverse)
- Connector responses are wrapped variably — always normalize via `normalizeConnectorResponse()`

### CRITICAL: Yes/No (Boolean) Fields — Use true/false, NOT 0/1

Dataverse Yes/No columns are `Edm.Boolean` at the OData level. The PAC CLI generates TypeScript enums with numeric keys (`{0: 'No', 1: 'Yes'}`) and types them as `0 | 1`, but the **OData API rejects integers** on boolean fields:

```
Cannot convert the literal '0' to the expected type 'Edm.Boolean'.
Cannot convert a value of type 'Edm.Int32' to the expected target type 'Edm.Boolean'.
```

**FIX:** Always use `true`/`false` for Yes/No fields in create/update payloads:
```typescript
// WRONG — PAC CLI type suggests this but Dataverse rejects it:
jw_requiresapproval: 0,
jw_allowmcp: 1,

// CORRECT — Dataverse OData API expects booleans:
jw_requiresapproval: false,
jw_allowmcp: true,
```

**Fields affected in jw_ model:**
- `jw_tools.jw_requiresapproval` (Yes/No)
- `jw_agents.jw_allowmcp` (Yes/No)

**Detection tip:** If a create silently fails with `success: false` and the error mentions `Edm.Boolean`, check for int-on-boolean fields. The generated TypeScript types are misleading — always verify against the actual Dataverse column type.

### CRITICAL: Check IOperationResult.success — Dataverse SDK Doesn't Throw on Failure

The PAC CLI SDK resolves the promise even when a CRUD operation fails. The `IOperationResult` has a `success` boolean that must be checked:

```typescript
const result = await Service.create(record);
// result.success might be false! result.data might be undefined!
// The promise did NOT reject — you must check explicitly.
```

`tracedOperation` in sdk.ts now checks this and throws on `success: false`, so errors propagate correctly. But always be aware that **unchecked raw SDK calls will silently swallow errors**.

### CRITICAL: Always Verify Field Names Against Generated Models

**Never assume a column exists.** The generated TypeScript interfaces in `src/generated/models/` are the source of truth for what fields exist on each entity.

Before adding ANY field to a create/update payload, verify it exists in the model:
```typescript
// Check: src/generated/models/Jw_instructionsModel.ts
// Fields: jw_name, jw_content, jw_type, jw_tags, jw_playbookid@odata.bind
// NOT: jw_ordernumber (doesn't exist!)
```

**Root cause of past error:** `jw_ordernumber` was used in seed data because conceptually instructions need ordering. But the field was never defined in Dataverse. The generated model only has `jw_name`, `jw_content`, `jw_type`, `jw_tags`, and `jw_playbookid`. Dataverse rejects unknown properties with:
> "The property 'jw_ordernumber' does not exist on type 'Microsoft.Dynamics.CRM.jw_instruction'"

**Prevention:** Before writing any CRUD payload, read the `*Base` interface from the generated model file. If a field isn't there, it doesn't exist.

### CRITICAL: Lookup @odata.bind keys must be LOWERCASE

The PAC CLI generates TypeScript interfaces with PascalCase lookup keys:
```typescript
// Generated interface (TeamsBase):
"BusinessUnitId@odata.bind": string;
"AdministratorId@odata.bind": string;
```

But the Dataverse OData API **rejects PascalCase** with error:
> `An undeclared property 'BusinessUnitId' which only has property annotations in the payload but no property value`

**FIX:** Always use lowercase in the actual payload:
```typescript
'businessunitid@odata.bind': lookupBind('businessunits', id)
'administratorid@odata.bind': lookupBind('systemusers', id)
```
Cast through `unknown` to bypass the typed interface when needed.

### System Entities vs Custom Entities (jw_ prefix)

**System entities** (teams, systemusers, businessunits):
- PAC CLI generates PascalCase lookup keys in TypeScript interfaces (`BusinessUnitId@odata.bind`)
- OData API requires **lowercase** (`businessunitid@odata.bind`)
- Must cast through `unknown` to bypass typed interface

**Custom entities** (jw_ prefix):
- Expected to use lowercase throughout (both interface and API)
- Verify after first `pac code add` for a jw_ entity — if PAC CLI generates PascalCase, apply same lowercase + cast pattern
- Lookup field names follow pattern: `jw_<targetentity>id` (e.g., `jw_agentid`, `jw_caseid`)

### Current User Resolution

**DO NOT** use `systemusers.getAll({ top: 1 })` — returns an arbitrary user, not the logged-in user.

**Correct pattern:**
```typescript
import { getContext } from '@microsoft/power-apps/app';

const ctx = await getContext();
const objectId = ctx.user.objectId; // Azure AD Object ID

systemusers.getAll({
  filter: `azureactivedirectoryobjectid eq '${objectId}'`,
  select: ['systemuserid', 'fullname', '_businessunitid_value'],
  top: 1,
});
```

`getContext()` returns `IContext` with:
- `user.objectId` — Azure AD Object ID (use to filter systemusers)
- `user.fullName` — Display name
- `user.tenantId` — Tenant ID
- `user.userPrincipalName` — UPN (email-like)
